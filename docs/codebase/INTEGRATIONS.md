# External Integrations

No database, no queue, no inbound webhooks. Everything is local files, subprocesses and optional outbound notifications. Settings come from `.env` (lookup in `config/envload.py`: `LOOP_ENV_FILE`, then `~/.loop-harness/.env`, then `plugin/shared/.env`; a real env var wins). See `app/.env.example` for the full list; secrets never go in the repo.

## Claude Code CLI

**Purpose:** executes every loop turn, planning and chat (`claude -p ... --output-format json`).
**Implementation:** `infrastructure/claude_client.py` (argv builder, no shell, env without secrets), `engine/cli_output.py` (tolerant parser), `services/claude_job_service.py`.
**Configuration:** binary from app config (`config/app_config.py`); `harness.py doctor` checks it is on PATH.
**Authentication:** the user's own Claude subscription; no API token.

## MCP servers

**Purpose:** sessions run with `--strict-mcp-config` and an empty config by default. A project may opt in (`ACCESS.json` `grafana_read`) to read-only Grafana/Loki.
**Implementation:** `engine/grafana_access.py` copies only the user's `grafana` definition from `~/.claude.json` into `<data dir>/.secrets/`, with an allow list of read tools and a deny list of write tools. `engine/access_settings.py` holds the per-project opt-in.
**Authentication:** the user's own MCP credentials; content never reaches argv, logs or responses.

## Git and GitHub

**Purpose:** worktrees, branches, push of the feature branch, pull request.
**Implementation:** `infrastructure/git_client.py`, `engine/delivery.py` (`gh pr create` or compare link), `engine/close_loop.py`, `services/loop_worktree_service.py`.
**Configuration:** `LOOP_INTEGRATION_BRANCH` / `LOOP_PR_BASE`, `LOOP_PR_MODE` (auto|link|off), `LOOP_PR_DRAFT`, `LOOP_GIT_USER`.
**Authentication:** the user's git identity and `gh` login. Never pushes to the integration branch directly.

## Notifications

**Purpose:** tell the user the loop stopped (awaiting decision, error, done).
**Implementation:** `engine/notify.py`, one `channel_<name>` function per channel registered in `CHANNELS`; email senders in `engine/email_senders.py`.
**Channels:** console, toast, file, email (SMTP or HTTP provider), webhook (POST JSON). A channel without configuration is skipped. `LOOP_NOTIFY_REQUIRED` makes the preflight fail if a channel is missing.
**Configuration:** `LOOP_NOTIFY_*`, `LOOP_SMTP_*`, `LOOP_EMAIL_HTTP_*`, `LOOP_WEBHOOK_URL`.
**Local-only extension:** `engine/local_ext/idata_backmail.py` (private email/WhatsApp provider; marked as not committed).

## Local panel API

**Purpose:** the panel and the engine talk over HTTP on 127.0.0.1.
**Implementation:** `api/http_server.py`, `api/router.py`, `engine/monitor_proc.py` (the loop registers a project with a running app through `~/.loop-harness/app.json`, header `X-Monitor-Token`).
**Authentication:** per-run token on mutating requests; `Host` check. The orchestrator skill never reads the token.

## Plugin hooks and skills bridge

**Purpose:** the plugin's guard hook blocks unsafe tool calls in agent sessions.
**Implementation:** `plugin/hooks/hooks.json` (PreToolUse, `guard.py --profile auto`), `plugin/skills/orchestrator/hooks/guard.py`; app side in `config/skill_locator.py`, `services/guard_event_service.py`. Contract in `app/docs/SKILL_BRIDGE.md`.

## Test environment credentials

**Purpose:** DEV-only test users for validators.
**Implementation:** `plugin/shared/testenv.py`, `repositories/test_environment_repository.py`, `services/test_environment_service.py`; values in `.specs/project/.env.test` or the `.env` files, never in markdown.

## Background jobs

No queue system. Long work is detached subprocesses (loop, panel) and threads in the app; the activity monitor stops the app after idle hours (`infrastructure/activity_monitor.py`).
