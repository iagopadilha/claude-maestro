# Project Structure

**Root:** claude-maestro (git repo, branches `main` and `developer`)

## Directory Tree
```
install.py                 one-command setup (config, doctor, plugin hints)
.claude-plugin/            marketplace manifest
plugin/                    the Claude Code plugin ("brain")
  agents/                  subagent prompts (executor-*, verifier*, spec-*, brownfield-mapper)
  skills/                  orchestrator (+ hooks/guard.py, references/), backend-dev, frontend-dev,
                           flow-validator, playwright-cli, orchestrator-* satellites
  shared/                  Python helpers and templates shared by skills (verify, testenv, sync_core...)
  hooks/hooks.json         hook registration
app/                       the control panel ("runtime")
  harness.py               single CLI entry
  backend/harness_backend/ Python back end (below)
  backend/tests/           unittest suites
  frontend/                index.html, src/, styles/, vendor/
  templates/               .specs templates copied into managed projects
  docs/                    ARCHITECTURE, API, HOW_TO_USE, MONITOR, SKILL_BRIDGE
docs/                      repo-level docs (media; codebase/ = these maps)
.specs/                    loop state of THIS repo (gitignored)
```

## Back end layers (`app/backend/harness_backend/`)
- `api/`: router, HTTP server, `controllers/*_controller.py` (HTTP <-> service only).
- `services/`: business logic; `*_module.py` files hold `build_*_module` wiring per module (loop read, loop commands, projects, multi-repo).
- `repositories/`: file access (`*_repository.py`). `infrastructure/`: process, git, claude CLI, logging, file guard.
- `domain/`: entities and errors. `config/`: app config, skill locator, env loading.
- `engine/`: the loop itself (`run_loop.py`, `loop_state.py`, `delivery.py`...), run as CLI subprocess or imported for pure reads.
- `demo/`: scripted demo (never runs a real loop). `composition.py` is the composition root.

## Frontend (`app/frontend/src/`)
- `main.js` entry; `pages/` (`hub.js`, `project_panel.js`, `repo_manager.js`, `pages/panel/*` panel sections); `components/` reusable widgets; `api/api_client.js`; `util/` helpers.

## Where Things Live
**A new HTTP route:** controller in `api/controllers/`, service in `services/`, file access in `repositories/`, wired in the module's `build_*_module` and `composition.py`; document in `app/docs/API.md`.
**Loop behavior:** prompt in `plugin/skills/orchestrator/` (SKILL.md, references/); runtime in `engine/`.
**Agent write limits / safety:** `plugin/skills/orchestrator/hooks/guard.py`, `infrastructure/workspace_file_guard.py`.
**A panel screen:** `app/frontend/src/pages/panel/`; styles in `styles/`.
**Project templates:** `app/templates/`.
**Tests:** `app/backend/tests/{api,engine,infra,demo}`; hook tests next to `guard.py`.

## Special Directories
- `app/backend/tests/engine/fixtures/`: CLI fixtures. `engine/local_ext/`: machine-local extensions, gitignored.
- `~/.loop-harness/` (outside the repo): runtime config and data.
