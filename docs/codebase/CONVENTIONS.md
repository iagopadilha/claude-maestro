# Code Conventions

Source of the rules: `app/docs/ARCHITECTURE.md` ("Construction rules"); the code wins.

## Naming (Python back end)
- Files: `snake_case.py`, singular with layer suffix: `project_service.py`, `answers_repository.py`, `repo_controller.py`; wiring files `*_module.py`.
- Classes: `ProjectService`, `AnswersRepository`, `RepoController`. Abstractions are `typing.Protocol` prefixed `I` (`IAnswersRepository`).
- Methods: verb + object (`append_pending_answer`, `list_repos`); avoid `process`/`handle`/`helper`/`manage`. Booleans read as questions (`is_loop_running`, `has_snapshot`).
- Constants: `UPPER_SNAKE` at module top, no magic numbers (`ACTION_TIMEOUT_SECONDS`, `REPOS_ROUTE`).

## Naming (front end)
- Files `snake_case.js` (`repo_manager.js`, `folder_browser.js`); components and pages are PascalCase functions (`RepoManager`); constants upper snake.

## Organization
- Layers: controller -> service -> repository -> infrastructure; domain in `domain/`. Constructor injection; only `composition.py` and `build_*_module` instantiate concrete classes.
- Controllers expose `register_routes(router)` and only translate HTTP; errors map through `respond_converting_errors`.
- Read, decide and write kept visibly separate.
- Imports: stdlib first, then relative package imports (see `services/action_service.py`).
- Front end: import Preact only via `util/preact.js`; markup with `html` tagged templates, no JSX, no build.

## Errors and logging
- Domain errors in `domain/project_errors.py`, converted to HTTP responses at the controller.
- Structured logging via `StructuredLog`; no `print` in the back end except the CLI.

## Comments and docs
- Each module opens with a docstring stating purpose and limits (see `repositories/answers_repository.py`). Comments explain why, not what.
- Code, identifiers, messages and docs in English.
- Type hints are sparse; Protocols are the main contract. Type-checker or linter config: not found.

## Security rules that shape code
- Listen on 127.0.0.1 only, token on mutating calls, body size limit, never return `.env` or credentials, actions only from a whitelist with `confirm:true`.

## Engine
- `engine/` is proven by its tests: change only what is needed; never rewrite the ROADMAP parser.

## Project-level
- `CLAUDE.md` sets conformance STANDARD: new code follows Api/Data/Domain on back end and pages/components on front end. Limiting rules go in `.specs/project/RULES.md`.
- Commits follow conventional style (`feat(plugin): ...`, `docs: ...`, `test: ...`).
